# Knowledge Base

This directory contains reusable engineering knowledge shared across software repositories.

## Knowledge Domains

| Directory | Purpose |
|---|---|
| `principles/` | Engineering principles and definition of done |
| `architecture/` | Architecture, APIs, distributed systems, and integration patterns |
| `development/` | Coding standards, code review, testing, and error handling |
| `security/` | Secure development and secrets management |
| `observability/` | Logging, metrics, tracing, and operational practices |
| `ai-engineering/` | Spec-Driven Development and AI agent guidelines |
| `templates/` | Reusable ADR, specification, and technical design templates |
| `decisions/` | Architecture Decision Records (ADRs) |

## Document Status

Every substantive knowledge document should declare one of these statuses:

- **Proposed** — awaiting engineering review.
- **Validated** — reviewed and approved for use.
- **Deprecated** — no longer recommended.
- **Superseded** — replaced by another document or decision.

## Authoring Guidelines

Each document should define:

1. Objective and problem addressed.
2. Status and applicability.
3. Rule or recommendation.
4. Rationale and trade-offs.
5. Examples and anti-patterns, where applicable.
6. Verification or compliance criteria.
7. References and supporting evidence.
8. Owner and last review date.

## Governance

Observed implementation patterns are not automatically approved standards.

Record the source of observed practices, distinguish facts from assumptions, and validate proposals before promoting them to engineering standards.
