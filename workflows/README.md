# Engineering Workflows

This directory documents reusable engineering processes.

BMAD-generated workflows should remain in the locations designated by the framework and its installer.

## Standard Development Lifecycle

1. **Discover** — understand the request, affected repositories, and constraints.
2. **Contextualize** — consult relevant knowledge and inspect the target code.
3. **Specify** — define behavior, acceptance criteria, dependencies, and risks.
4. **Design** — document material technical decisions and contract changes.
5. **Implement** — make focused changes and add automated tests.
6. **Verify** — run tests and applicable quality and security checks.
7. **Review** — evaluate the implementation against specifications and standards.
8. **Learn** — propose knowledge updates based on validated findings.

## Workflow Scaling

Small, low-risk changes may follow a lightweight process.

Changes involving architecture, security, data integrity, external contracts, or high operational risk require deeper specification and review.
